Negative/concurrency cases: unauthenticated and wrong-role direct URLs, another student's pass, inactive users, full events, closed periods, duplicate simultaneous registration, duplicate check-in, cancelled registration, wrong-event pass, invalid uploads, malformed/partially invalid CSV, expired sessions, and conflicting edits.

`ConcurrencyTests` runs synchronized authenticated HTTP request pairs on an owned, disposable SQL Server LocalDB instance; see [setup](SETUP.md) for prerequisites and isolation/cleanup. Each pair must reach its SQL/save gate on two distinct open SqlClient connection IDs. Booking gates run after eligibility/capacity/duplicate preflight but before SaveChanges; scanner gates precede the conditional admission UPDATE; account-edit gates precede SaveChanges while Serializable transactions hold their snapshots; cross-admin removal gates synchronize the actor-access reads inside both transactions. Each scenario repeats five times with freshly seeded fictional rows. Fresh contexts verify committed state, counters, password hashes, rollback, stable timestamps and stale-snapshot/cookie rejection. A shared rollback transaction or a test that merely starts two tasks does not establish this coverage.

`AuthenticationTests` and `DatabaseFoundationTests` share the `Shared SQL rollback fixtures` xUnit collection. Their long-lived rollback transactions can lock overlapping tables, so these fixture classes must not run against the same catalog in parallel. This collection does not serialize the concurrent HTTP requests within `ConcurrencyTests`, which owns a different SQL instance. The demo-data test intentionally requires the localhost/default SQL instance because the production seeder rejects other server targets; a LocalDB regression override must explicitly exclude that case and report it as not rerun rather than weaken the seeder's guard.

A feature is done only when required behavior is implemented, its reference-led UI is consistent and accessible, server authorization/validation is enforced, relevant checks pass, affected documentation files are current, and work is committed. Report any checks not run and why. Final release checks include clean dependency restore, .NET build/test/publish, frontend production build and generated CSS inclusion, and validated database setup for both supported paths.
